As is the popular consensus - There is no meaning to computers if they don't make our life faster. This field of hardware optimizations, accelerators has rapidly evolved with the singular motivation of making computation faster cheaper and lesser without losing out on output accuracy and precision. Given the heavy demand for compute, optimization efforts have percolated every layer of the vertical compute stack from model algorithms to circuit design.

Recently I read a survey paper that reveals these multi-fold efforts for optimization made across different layers in the processing of deep neural networks. This blog aims to provide a 10k feet view of how various levels in the vertical compute stack are being optimized and stitched together blurring boundaries in the vertical stack.

Neural Network: First Train then Inference
Models are charascterized by their architecture and parameter values. Parameter values are determined through a process called training. This is a long iterative process and there are several methods to speed up stabilize the process for example batching. Once training is complete the model is ready for use(inference). The resources and precision required for training is more than inference. Also inference is often carried out on embedded devices. This severely constraints compute capability and power. We explore a lot of techniques that have been introduced to reduce the size, computation power needed for inference while maintaining minimum accuracy loss.

Where can we cut (extra) cost?

  • Reduce Model Complexity
  • Reduce Number of Operations
  • Reduce Communication Cost
  • Designing New Hardware

Each of the above points are optimized on in several different way and we will look at them one by one.

Reducing Model Complexity -
Model Complexity refers to the effective capacity of models to represent and learn complex data patterns. Model complexity comes from non linear operations, number of parameters (model size), precision of model parameters and the most importantly the model architecture.

  • Model Architecture and Model Size:
    Depending on the task at hand, embedded devices should use models that are designed for the specific task and gauge the model size based on the complexity of the data they have to handle. Models can employ sparse connections and use dimensionality reduction to reduce complexity. Weight sharing and decomposing filters are popular methods to reduce model size.
  • Parameter Precision:
    Reducing weight precision has been a popular way to simultaneously reduce both memory requirements and computation costs. The major drawback to this and the reason why one cannot indefinitely reduce preciosion is lack of accuracy. There do exist neural networks that work on binary or ternary weights. This method is called quantization. Normalizations are used to keep values from overflowing or underflowing limits. Precision is reduced more for inference than for training process. This is because in training : rradient values accumulated over backpropogation are susceptible to accuracy loss on reduced precision sevrely impacting the accuracy of the model.
  • Pruning Models:
    After an overparameterized model is trained, this method reduces model sizes and removes redundancy in weights. This is followed up with fine-tuning the remaining weights to make up for the lost accuracy. Coarse grained pruning can be more harmful to accuracy while facilitating better compression which allow for higher memory savings and reduced computations.
  • Compressing Sparse Models for energy and area savings. How can sparse models be compressed efficiently? Sparse models also reduce computation costs if their sparsity is well exploited. Structured sparsity that arises from structured (coarse-grained) pruning allows greater savings than fine grained pruning.
  • Knowledge Distillation:
    This technique is used to train smaller models from foundational models allowing them to learn information faster and in a more compressed way. These are well suited for embedded devices.

Reducing Number of Operations -

  • Algortihmic reductions:
    Applying data transformations to reduce the number of operations needed. Eg. Fast Fourier Transform.
  • Detecting Zero-Multiplications:
    Can we null out small values? Can we detect and skip multiplication with zero - thus saving power?

Reducing Communication Cost -

  • Using full memory bandwidth: Coalesced and non-conflicting access to memory units to reduce latency and maximize utilization.
  • Communication costs increase with distance and hence effort is directed towards making optimum use of memory closest to compute. Reducing memory accesses by maximizing data reusage in the compute before new data is pulled is the goal. Different algorithms that maximize reuse of different data elements like input activations, weights, partial results or combinations of these in different proportions are compared.

Designing New Hardware -

  • Several neural networks are popular across fields and used heavily. Further the fixed architecture and lack of randomness allows the creation of fixed data workflows.
  • Often a particular computation needs to be carried out many number of times. Adding new hardware to support efficient computation of some model specific operation for example Multiply-an-Accumulate units.
  • New accelerators to speed matrix multiplication, convolution, vector-matrix multiplications etc.
  • Memory close to compute or compute in memory to reduce communication cost and latency.
  • Temporal Vs Spatial Architectures.
